Finance API Documentation

Overview

The Finance API provides endpoints to access financial data related to expenses, revenue, budgets, past due accounts, and employee information. All endpoints are accessible via HTTP GET requests.

Authentication

Most endpoints allow read access without authentication. However, create, update, and delete operations require authentication with admin privileges (email: admin@santaclarautah.gov).

Base URL

/api/finance

Endpoints

1. Expense Details

GET /expense

Retrieves detailed information about expenses.

Query Parameters

Parameter Type Required Description
fund Integer No Filter by fund number
gl String No Filter by GL account number
start_date String (YYYY-MM-DD) No Start date for filtering
end_date String (YYYY-MM-DD) No End date for filtering

Response

JSON Response
[
  {
    "fund_no": 10,
    "gl_account": "10-4000-100",
    "account_name": "General Fund Expenses",
    "type": "Invoice",
    "description": "Office Supplies",
    "date": "2023-06-15",
    "amount": "245.67"
  },
  ...
]

5. Employee Information

GET /employee

Retrieves employee information.

Query Parameters

Parameter Type Required Description
hire_date_start String (YYYY-MM-DD) No Filter by hire date start
hire_date_end String (YYYY-MM-DD) No Filter by hire date end
status Integer No Filter by employment status (1 for Active, 0 for Terminated). Defaults to Active if not specified.

Response

JSON Response
[
  {
    "first_name": "Jane",
    "middle_name": "Marie",
    "last_name": "Smith",
    "department": "Finance",
    "position": "Accountant",
    "type": "Full-time",
    "hire_date": "2020-03-15",
    "rehire_date": "2020-03-15",
    "termination_date": "2023-12-31",
    "status": "Active"
  },
  ...
]

Data Connections

All endpoints connect to the 'finance' database connection as specified in the application configuration.

Notes

Important Information
  1. All monetary values are formatted to 2 decimal places.
  2. All dates are returned in the format YYYY-MM-DD.
  3. Revenue amounts are multiplied by -1 to represent a positive value.
  4. By default, the Employee endpoint only returns active employees unless specified otherwise.

Error Handling

The API will return appropriate HTTP status codes:

Status Code Description
200 Successful request
400 Bad request (invalid parameters)
401 Unauthorized (for protected operations)
500 Server error
